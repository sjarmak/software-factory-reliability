# Style rules for contributors

These rules are enforced by `src/checks/prose_check.py` (run via `make
prose-check`). This file quotes the banned list, so the checker exempts it
from the phrase rules; the em dash rule still applies here. AGENTS.md and
CLAUDE.md contain tool-managed blocks (regenerated by `bd`), so the checker
exempts those two files from the phrase rules as well; the em dash rule has
no exemptions anywhere in the repository, and a regeneration that
reintroduces an em dash will fail `make prose-check` until the text is
recast.

## Banned outright

Characters:

- The em dash (U+2014) is banned everywhere in the repository: prose, code,
  comments, YAML, JSON, docstrings. Use commas, semicolons, parentheses, or
  recast the sentence. The en dash (U+2013) in prose draws a warning; prefer
  "to" or a hyphen in ranges.

Phrases (case-insensitive, all hard failures):

- "delve"
- "it's worth noting"
- "here's the thing"
- "the key insight"
- "the real question"
- "let's unpack"
- "this changes everything"
- "game-changer"
- "honest caveat"
- "to be honest"
- "seamlessly"

Constructions (warned or caught in review):

- Rhetorical questions answered in the next sentence.
- "This isn't just X, it's Y" and any other not-X-but-Y contrast formula.
- Three-item rhetorical crescendos.
- Stacks of consecutive one-line paragraphs (more than three in a row).
- Headings that read like product marketing.
- Trailing summary sections that restate the page.
- Agreement-performance openers ("you're right", "great point", "good catch").
- Sentence-initial "Crucially,", "Fundamentally,", "Importantly,".
- "not just" more than twice in one file.

## The structural rule for pattern pages

A pattern page must name all four of these, explicitly:

1. **An invariant**: a precise safety or liveness statement over the whole
   system, not over one component. "The engine recovers" is not an invariant;
   "one logical effect ID leaves one physical effect" is.
2. **An enforcement boundary**: the layer that rejects violations, named
   concretely enough that a reviewer can check the enforcement lives there.
   A fence checked by the caller does not enforce a destination-side promise.
3. **A falsifying test**: the fault injection that would break the invariant
   if the enforcement were absent, including where the kill or delay lands.
   The unsafe control must fail the oracle; a drill whose unsafe mode passes
   is testing nothing.
4. **The evidence retained**: what the executed test leaves behind (ordered
   event logs, receipts, exit statuses) and where it lives.

A page that cannot name all four is not ready to merge. Park it in a draft
until it can.

## Evidence-basis labels

Every factual claim carries one of four labels. Never present an inference as
an established result.

- **foundational**: established distributed-systems literature. Example:
  fencing tokens prevent a stale lease holder from writing after expiry
  (Kleppmann 2017).
- **agent-era**: published work on agent systems. Example: a planner-to-
  subagent search design attributed 41.8 percent of its failures to handoff
  loss (manuscript ch17, citing Oskooei et al. 2026).
- **local observation**: the production installation, the durability lab, or
  the book manuscript's experiments, always with a file path. Example: all 18
  unsafe trials recorded two external effects under one recorded completion
  (temporallab2026:docs/guarantees.md).
- **inference**: our synthesis, not yet demonstrated. Example: conflict-graph
  scheduling of agent fleets should reduce cross-agent interference; no end-
  to-end demonstration exists yet.

## The paragraph rule

Every paragraph must add at least one of: a mechanism, an observation, a
qualification, an example, or a consequence. A paragraph that restates the
previous one in different words, or that exists to build rhetorical momentum,
gets cut. Apply the same rule to sentences within a paragraph when editing:
declarative, concrete, varied rhythm.

## Dates and vendors

All dates are absolute (2026-07-15, never "last month"). Normative text is
vendor-neutral; naming a system inside an evidence citation is fine, and
recommending one is not.
